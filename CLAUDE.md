# Color-Chan Wiki

This is the [official documentation wiki](https://wiki.colorchan.com/) for the Color-Chan Discord Bot. Here, you will find everything you need to get started with Color-Chan, including guides, FAQs, and detailed explanations of its features.

The site is a content repo, not an application: there is no application code, only Markdown content and Zensical theme/config. The documentation is built with [Zensical](https://zensical.org/) (the successor to Material for MkDocs, same config surface).

## Commands

Always test/verify changes via the provided Docker Compose setup. Do **not** `pip install zensical` locally to test — even though CI uses pip (see below), local verification must go through Docker:

```bash
docker compose up -d            # serves at http://127.0.0.1:7562, live-reloads on file changes
docker logs color-chan-wiki     # check build output / "No issues found"
docker compose down
```

CI build only, for reference — not for local testing (`.github/workflows/build-wiki.yml`): 
```bash
pip install zensical
zensical build --clean
```

There are no tests, linters, or package manifests in this repo — verification means running the Docker build/serve above and checking the output for build errors or by curling the served HTML.

## Architecture

- **`zensical.toml`** — single source of site config: theme, palette, features, markdown extensions, `extra.social`, `extra.analytics`. There is no `nav:` section, so navigation is derived from the `docs/` directory structure.
- **`docs/`** — all page content, in Markdown with YAML frontmatter (`title`, `description`). Structure:
  - `docs/index.md` — homepage
  - `docs/documentation/` — main docs, subdivided into `colors/`, `permissions/`, `configurations/`, `slash-commands/`, `premium/`, `common-issues/`
  - `docs/FAQ/`
  - `docs/img/` — screenshots/gifs referenced by docs pages
  - `docs/robots.txt`
- **`overrides/`** — Zensical/MkDocs theme override directory, wired in via `project.theme.custom_dir = "overrides"`. Currently contains `overrides/partials/integrations/analytics/custom.html`, a custom analytics partial (Umami-style script tag) selected via `[project.extra.analytics] provider = "custom"`. This is the pattern to follow for any further theme customization: mirror the theme's partial path under `overrides/` and reference it through config rather than editing theme internals directly.
- **`site/`** — generated build output (gitignored). Never hand-edit; it's regenerated by `zensical build`.
- **Deployment**: `wrangler.toml` configures Cloudflare Pages to serve `./site` as `pages_build_output_dir`. CI (`.github/workflows/build-wiki.yml`) builds the site with `zensical build --clean` on push to `main`/`dev`; Cloudflare Pages picks up the build output from there.

## Editing content

- Add new pages as `.md` files under `docs/`; nav placement follows the directory/file layout (no manual nav config to update).
- Keep frontmatter (`title`, `description`) consistent with existing pages for SEO/search.
- Reference images from `docs/img/`.
